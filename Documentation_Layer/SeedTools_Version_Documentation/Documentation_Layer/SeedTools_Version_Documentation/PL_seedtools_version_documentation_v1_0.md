# **🔥 1. Kiedy dokumentacja MUSI mieć wersję?**

Jeśli dokument:

- definiuje standard,  
- opisuje framework,  
- jest częścią architektury bezpieczeństwa,  
- jest częścią RX‑Series lub FA‑Series,  
- jest częścią modułów ransomware,  
- jest częścią Enterprise Architecture,  
- jest częścią Governance, Compliance, Recovery, Defense, Security, Audit,

→ **musi mieć wersję**.

### Przykłady:

- **PL_seedtools_ransomware_compliance_standard_v1_0.md**  
- **PL_seedtools_ransomware_recovery_framework_v1_0.md**  
- **PL_seedtools_enterprise_security_charter_v1_0.md**  
- **PL_seedtools_post_incident_governance_framework_v1_0.md**  
- **PL_seedtools_ransomware_defense_matrix_v1_0.md**  
- **PL_seedtools_ransomware_severity_index_v1_0.md**  
- **PL_seedtools_encryption_timeline_v1_0.md**  
- **PL_seedtools_forensic_workflow_v1_0.md**

To są dokumenty **formalnych standardów**, więc wersja jest obowiązkowa.

---

# **🔥 2. Kiedy dokumentacja NIE musi mieć wersji?**

Jeśli dokument:

- jest instrukcją,  
- jest przewodnikiem,  
- jest workflow operacyjnym,  
- jest dokumentem pomocniczym,  
- jest indeksem,  
- jest standardem repo lub folderów,  
- jest onboardingiem,  
- jest dokumentacją Rustup,  
- jest przykładem,  
- jest PDF-em,

→ **nie musi mieć wersji**.

### Przykłady:

- **PL_seedtools_documentation_workflow.md**  
- **PL_seedtools_documentation_index.md**  
- **PL_seedtools_folder_naming_standard.md**  
- **PL_seedtools_repo_standard.md**  
- **PL_seedtools_onboarding_guide.md**  
- **PL_rustup_backup_workflow_deterministic_safe.md**  
- **PL_rustup_restore_workflow_deterministic_safe.md**  
- **SeedTools_Rustup_Migration_Guide.pdf**  
- **deterministic_test_output.txt**

To są dokumenty **operacyjne**, nie formalne — wersja nie jest wymagana.

---

# **🔥 3. Zasada SeedTools Enterprise (najważniejsza)**

### **Jeśli dokument wpływa na bezpieczeństwo → ma wersję.**  
### **Jeśli dokument wpływa na workflow → wersja nie jest wymagana.**

To jest fundament całej Arrchitektury.
